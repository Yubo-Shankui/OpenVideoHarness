# 05 纯代码场景与合成

本 fork 没有视频生成或转绘模型工具。原“写实人物、真实物理、实拍感”需求进入本管线；不改变其他不涉及视频生成的路由。

写实人物优先 Blender 或 Three.js，显式实现模型、骨骼/关节、动作和相机。按需求选引擎，不强制所有内容三维化。Blender 用法见 engines/blender.md；Three.js 可作为 HyperFrames 场景层。原有剪辑、字幕、图表、特效、音频与合成能力保留。

## 四种可组合模式

- **A · 直接制作镜头**：文字与允许的 keyframes → 代码建场景、做动画 → 渲染视频 → 剪辑。写实人物优先 Blender / Three.js。
- **B · 底片与叠加**：代码渲染底片 → 叠字幕、图形、特效。若底片为调用方允许的已有素材，保留原剪辑合成流程。不能因本模式而获得额外 GT 素材权限。
- **C · 粗模到细化**：粗模确定构图、动作和机位 → 在同一工程细化几何、动画、材质和光照 → 直接渲染输出；不再交视频模型加工。
- **D · 动作与风格转换**：代码动画 → 程序化转描或风格化渲染。可用自建三维场景的轮廓、遮罩、深度交给 Canvas/SVG/p5 绘制，或用卡通材质、描边、shader 直接三渲二；简单二维动作可直接绘制。不调用转绘模型。

A 是镜头制作，B 是合成，C 是逐步细化，D 是风格转换；没有互斥分类或均衡配额，agent 根据需求选择和组合，并记录理由。

## 与调用方 harness 的接口

仅使用调用方允许的文字、keyframes、资产和观察权限。隔离制作侧不可读取 GT、隐藏抽帧或评审历史；非隔离侧按实验授权观察 GT，不能直接播放 GT 充当重建。代码场景和素材可跨轮继续修改。

不强求照片级真实，但应忠实表达动作、交互、时序、构图与运镜。实现不了的部分明确记录，不因缺少视频模型而默认用首帧平移替代复杂动作。沿用原确定性渲染、自查和合成工具；状态型模拟须先烘焙，支持按时间确定性取帧。

底片调色、颗粒、抠像和合成细节按需参考 [代码底片合成参考](05-code-compositing-reference.md)，保持原有合成能力。
